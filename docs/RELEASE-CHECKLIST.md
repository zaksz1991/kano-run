# Kano Life — Release Safety Gate

This upgrade prevents a repeat of the Vercel error where JavaScript game-engine code was accidentally pasted into the root `index.html`.

## What it checks

- Syntax of JavaScript modules under `js/`, `api/`, `scripts/`, and `tests/`.
- `package.json` module mode and Three.js/Vite dependencies.
- Exactly one HTML document root and body, one doctype, a clean closing tag, and a `/js/main.js` entry.
- Common signatures of JavaScript source accidentally pasted into HTML.
- Existence of local relative imports from JavaScript modules.
- Local assets referenced by `<script>` and `<link>` tags.
- The built `dist/index.html` after Vite finishes building.

## Installation

1. Merge `scripts/`, `.github/workflows/`, and `docs/` into the repository root.
2. Replace `package.json` with the included complete file. It keeps the project's existing name, version, Three.js version range, and Vite version range while adding checks.
3. Preserve your existing `package-lock.json`. Since dependencies are unchanged, `npm ci` should still use the lockfile. If npm reports a lockfile mismatch, use the lockfile generated by your project before pushing; do not delete it blindly.
4. Run the checks below locally before committing.

## Commands

```bash
npm run check:syntax
npm run verify
npm test
npm run build
npm run verify:dist
```

Or run all steps in sequence:

```bash
npm run release:verify
```

## CI deployment gate

The included GitHub Actions workflow runs on pushes and pull requests targeting `main`. It fails the check when syntax, HTML structure, local imports, tests, the Vite build, or built HTML validation fail. It does not deploy the application by itself; Vercel continues to handle deployment according to its existing Git integration settings.

## Limits

A successful release gate does not prove WebGL visuals are correct, all GLB files load, or the game holds 60 FPS. It only blocks common source-structure and build failures. Test the game in desktop and mobile browsers after deployment.
