# Kano Life — Step 97: Road-Path Continuity & Reverse-Aware Junction Progress

## Download and install

This update is made for the existing static Kano Run project. It does not require a `harness` folder, `boot.py`, a package file, or terminal-based installation.

1. Download and extract `Kano-Life-Step97-Road-Path-Continuity.zip` with File Explorer.
2. Open `kano-step97-package/js`.
3. Replace the complete `KanoModelAssetVisualUpgrade.js` and `KanoRoadNavigationUpgrade.js` in the project's `js` folder.
4. Add the new `KanoRoadPathContinuityUpgrade.js` to that same folder.
5. `KanoRoadWorldCoordinatesUpgrade.js` is included unchanged as the Step 96 baseline. Keep the project's current copy; replace it only if you have not applied Step 96 yet.

Keep `index.html`, `main.js`, `game.js`, `ui.js`, the renderer files, storage, model assets, and saved browser data unchanged.

## What Step 97 changes

### 1. One signed coordinate drives junction progress

The route guide now reads `game.kanoWorldDistanceKm`, the same signed coordinate used by Step 96's flyover and junction anchors. The official career odometer remains forward-only; it is no longer incorrectly used to decide which junction is physically nearby while reversing.

### 2. Reverse-aware junction re-approach

While backing up, the current forward junction choices stay disabled. The navigation target repositions to the nearest previous scheduled junction. Once the vehicle backs beyond the 45 m pass band, the target moves to the prior junction. When the driver changes back to forward gear, the guide selects the physically upcoming junction again. The existing 35 km/h left/right turn limit and 12 km/h U-turn limit remain in force.

### 3. Fresh runs are re-based

The code order in the current engine means world distance is assigned by the Step 96 wrapper after the Step 95 navigation start hook. Step 97 rebases the junction target after that reset, preventing a later run from inheriting stale route-progress coordinates.

### 4. Local path-continuity trace

A small `kanoRoadPath` state follows signed travel through existing heading transitions, recording projected X/Z position, direction, route changes, turn headings, and reverse distance. It is capped at 64 route breadcrumbs and remains in memory in the current browser session; it is not sent to a server or saved into the user's wallet/profile data.

When the route guide is visible, it also shows the current route, compass heading, and whether the player is in forward or reverse.

### 5. Local diagnostic

In browser DevTools, run:

```js
window.kanoRoadPathContinuityAudit()
```

The audit reports the current signed coordinate, projected path position, current road/heading, turn history, next junction target, and checks that the values are finite.

## Scope limits

This is an integration and continuity step. It improves signed navigation progress and records an arcade path projection, but it does **not** yet replace the vehicle engine with wheel/tire physics, add realistic traction, create a surveyed Kano street map, or make every roundabout a fully traversable closed-loop path. Flyover deck driving and fully connected road paths still need a later vehicle/world-topology implementation. Do not represent this step as finishing those features.

InstantMesh remains part of the asset plan. InstantMesh inference was not run in this step and no included mesh is claimed to have been generated by it.
